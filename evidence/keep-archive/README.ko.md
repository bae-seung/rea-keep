# Google Keep 보관·보관 해제 시험 분석

## 결과

사용자가 별도 Chrome에서 로그인한 뒤 `http://127.0.0.1:9226`에 REA로 연결했다. 지정한 테스트 메모 한 개를 생성해 보관 → 보관 해제를 수행했으며, 페이지를 다시 로드한 뒤 제목·본문과 상태가 유지되는 것을 확인했다. 최종 메모는 **보관 해제 상태**로 남아 있다. 재현 앱 개발은 하지 않았다.

- 제목: **REA 과제 테스트**
- 본문: **보관 및 보관 해제 동작 확인**
- 대상: `https://keep.google.com/`
- 환경: REA 6.8.0, Chrome 156.0.8078.81, 기존 개인 프로필을 복사하지 않은 사용자 실행 분석 세션
- 기존 개인 메모를 열거나 수정하는 동작은 수행하지 않았다. 초기 목록 화면의 배경 정보가 원시 관찰에 포함되어 제출물에서는 제외했다.

보관 후와 보관 해제 후 화면은 각각 해당 동작을 실행하고 2초 대기한 다음 **같은 테스트 메모 URL로 다시 이동해 로드한 화면**이다. 마지막 검증은 별도 REA 시나리오의 시작 탐색으로 같은 문서를 추가로 다시 로드했다. 브라우저 새로고침 단축키 대신 문서 재탐색을 사용했다. 이는 동일 브라우저 세션의 재로드 지속성 검증이며, 다른 기기 동기화나 브라우저 완전 종료 후 유지까지 검증한 것은 아니다.

접근성 결과에서 제목 textbox의 값이 생략되므로, 제목은 REA 스크린샷과 DOM 내 정확한 제목 존재 여부로 교차 확인했다. 본문과 보관 상태는 접근성 결과에서도 확인했다. 원본 DOM은 개인정보 때문에 제출하지 않았다.

## REA 호출과 증거

- `list_browser_targets`: 연결 성공 및 탐색 후 대상 재확인.
- `inspect_web_page`: 초기 UI 제어 요소 확인. `observation_ms: 0`, 인증 완료 후 실행. 원시 결과에는 초기 목록/계정 메타데이터가 포함될 수 있어 제출하지 않았다.
- `capture_browser_scenario`: 입력, 테스트 메모 열기, 보관/보관 취소 클릭, 재로드, 접근성·DOM·스크린샷 관찰. 이벤트 수집 `events: []`, 요청/응답 본문·헤더·스토리지 캡처 미선택.
- `capture_web_screenshot`: 별도 호출은 `target_unavailable / target_changed`로 실패했다. 제출한 스크린샷은 이 호출이 아니라 **성공한 `capture_browser_scenario`의 screenshot artifact**다.
- REA CLI `doctor --client codex --json`: 시나리오 오류 안내에 따라 읽기 전용 진단. Node 및 Codex 등록 정상. 선택적 네이티브 엔진 미설치 항목은 이번 웹 UI 작업의 필수 조건이 아니다.

정확한 호출 인자·성공/실패·단계 상태는 [calls.sanitized.json](calls.sanitized.json), 화면별 Evidence ID·선택한 접근성 결과·원본 이미지 해시는 [observations.sanitized.json](observations.sanitized.json)에 기록했다. 테스트 메모의 식별 URL은 `TEST_NOTE_ID`로 치환했다. 이 파일들은 **개인정보를 제외한 발췌 기록**이며, 완전한 원시 REA Evidence 내보내기가 아니다.

## 실패와 복구

이전 연결 실패 기록은 [previous-connection-failure.ko.md](previous-connection-failure.ko.md)에 보존했다. 이번 재연결은 성공했다.

1. 검색 입력 시도는 테스트 메모 격리 성공으로 판단하지 않았다. 이후 생성한 메모의 정확한 본문으로 클릭하고, 관찰된 고유 메모 URL로 범위를 한정했다.
2. `메모 작성…` 안내 텍스트 클릭은 입력 요소의 포인터 가로채기로 timeout. 실제 `contenteditable` combobox를 확인하여 본문을 입력했다.
3. 다음 호출의 초기 탐색으로 작성 폼이 닫혀 제목 입력이 timeout. 새 메모를 추가 생성하지 않고, 이미 저장된 정확한 본문의 메모를 열어 제목을 입력했다.
4. 제목 입력은 completed였으나 이어지는 닫기 과정에서 `execution_failure`가 반환됐다. 반환된 부분 관찰에는 메모 열기와 제목 입력 완료가 기록되어 있다. 닫기 성공을 추정하지 않고, 진단과 대상 재조회 후 동일 메모의 제목·본문을 다시 관찰하여 저장 여부를 확인했다. 오류의 내부 원인은 미확인이다.
5. 별도 스크린샷 호출은 `target_changed`로 실패했다. 대상 재조회 후 안정화 대기와 테스트 메모 직접 탐색을 사용한 후속 시나리오에서 캡처했다.

## 관찰과 구현 추정의 경계

**관찰:** 동일 테스트 메모에서 보관 UI가 양방향으로 전환되고, 재로드 후에도 그 상태와 내용이 보였다. 본문을 저장하는 동작은 한 번만 실행했고, 이후 그 메모에 제목을 설정했다.

**추정:** 이 UI는 메모의 보관 여부를 전환하는 상태 모델로 설명할 수 있다. 그러나 서버가 boolean 필드를 사용하는지, 어떤 API·DB·동기화·캐시 구조인지 확인하지 않았다. 재로드 유지로 서버 저장 완료나 다른 기기 동기화를 단정할 수 없다. 네트워크 본문·서버 내부 분석은 수행하지 않았다.

**과제 후보 판단:** 이 좁은 범위의 UI 상태 전환과 재로드 결과는 반복 가능한 과제 명세의 근거로 사용할 수 있다. 서버 동작의 완전한 복제 가능성까지 입증한 것은 아니다.

## 개인정보 처리와 파일 무결성

로그인 과정은 사용자가 수행했고 로그인 중 네트워크 기록을 시작하지 않았다. 이후 시나리오도 네트워크 이벤트·본문·헤더·스토리지 수집을 요청하지 않았다. 초기 수동 관찰의 전체 결과와 전체 DOM은 제출하지 않는다. 원시 REA 관찰 일부는 도구 세션에 남을 수 있지만 제출 폴더에는 저장하지 않았다.

2560×1440 원본 스크린샷에서 테스트 메모 모달만 잘랐다. crop 좌표는 원본 기준 `x=600, y=258, width=1200, height=427`이며, 계정 표시와 배경 개인 메모를 제거했다. 캡처 내용 자체를 합성하거나 수정하지 않았다. 잘라낸 네 이미지 모두 시각 검수했다. 제출 파일 SHA-256은 [SHA256SUMS.txt](SHA256SUMS.txt)에 있다.

전체 원본 이미지의 임시 파일은 검수 후 삭제했다. Chrome 프로필·쿠키·인증 정보는 제출 폴더에 포함하지 않았다. 분석용 Chrome과 테스트 메모는 사용자가 계속 확인할 수 있도록 남겼다.
