# REA 메모 앱

Spring Boot·Thymeleaf·MySQL로 구현한 로컬 과제 앱입니다. 메모 작성·수정·목록, 보관함, 검색, 휴지통·복원·영구 삭제, 체크리스트, 라벨 관리·라벨별 조회, 고정·색상 변경을 제공합니다. Google Keep의 구성에서 참고했으며 원본 UI·서버 구현과 같다고 주장하지 않습니다.

- Java **21**, Spring Boot **4.0.9**, Maven Wrapper **3.10.0**.
- Spring Web MVC, Thymeleaf, Data JPA, Validation, MySQL Connector/J. 의존성은 Boot BOM 관리.
- Controller → Service → Repository. 서버는 `127.0.0.1:8080`에만 바인딩합니다.
- DB: `jdbc:mysql://127.0.0.1:3306/rea_keep`. `DB_USERNAME`, `DB_PASSWORD` 환경변수 사용.
- [개발 기록](docs/development-log.md) · [원본·구현 비교표](docs/feature-comparison.md) · [실행 검증 현황](docs/runtime-verification.md).
- [PPT2 제출 요약](docs/submission-summary.md): 환경·도구·분석 근거·구현·검증 범위·오류 해결·발표 캡처 경로.

Java 21 지원 범위와 의존성은 [공식 시스템 요구 사항](https://docs.spring.io/spring-boot/4.0/system-requirements.html) 및 [공식 관리표](https://docs.spring.io/spring-boot/4.0/appendix/dependency-versions/coordinates.html)를 확인해 선택했습니다.

## 한 번에 DB 준비·서버·검증 브라우저 시작

실제 MySQL 인증은 사용자의 일반 터미널에서 한 번 수행합니다. 기존 앱이 실행 중이라면 먼저 종료합니다.

```bash
cd /Users/baeseungjun/Projects/rea-assignment
./app/scripts/prepare-and-run.sh
```

스크립트는 다음 순서로 동작합니다.

1. Java 21 선택, 8080 포트 사용 여부 확인, `./mvnw verify` 실행. 실패하면 중단합니다.
2. 비밀번호를 `read -r -s`로 숨겨 한 번 입력받습니다. 명령 인자·파일·로그에 저장하지 않습니다.
3. `--prepare-db` 전용 CLI가 기존 테이블과 열을 조회한 뒤 **없는 테이블/열만 추가**합니다. 기존 행 삭제·초기화·본문 수정은 하지 않습니다.
4. 같은 환경변수로 서버를 시작하고 별도 임시 프로필 Chrome을 엽니다. 앱용 CDP는 `127.0.0.1:9227`, 원본 분석용 9226과 분리합니다. Chrome에는 DB_PASSWORD를 전달하지 않습니다.
5. Codex가 이 브라우저에서 과제용 테스트 데이터만으로 검증합니다. 인증 후 터미널을 열어 두고 시작 여부만 알려주면 됩니다. 기능마다 사용자가 수동 검사를 할 필요는 없습니다.

서버 재시작은 `app/target/restart.request` 파일 생성으로 요청할 수 있습니다. 스크립트는 자신이 시작한 서버 프로세스만 종료·재시작하며 비밀번호를 다시 파일에서 읽지 않습니다. 비밀번호는 실행 중 프로세스 환경에만 유지됩니다. 종료는 `Ctrl+C`; 변수도 해제합니다. 별도 Chrome은 직접 닫을 수 있습니다.

DB 준비 실패 시 예외 종류만 출력하며 인증정보나 예외 원문은 출력하지 않습니다. 스키마가 예상과 다르면 자동으로 수정·삭제하지 않고, 이후 Hibernate `validate`가 시작을 거부할 수 있습니다. MySQL DDL은 자동 커밋되므로 전체 변경의 롤백을 가정하지 않습니다. 적용이 일부 완료됐다면 원인을 해결한 뒤 재실행하면 이미 존재하는 항목은 건너뜁니다.

## 스키마와 기존 데이터 보존

| SQL | 추가 내용 | 기존 메모 처리 |
|---|---|---|
| `001-create-notes.sql` | 기본 메모 테이블 | 테이블이 없을 때만 생성 |
| `002-add-archived.sql` | archived | 기본값 false |
| `003-add-trashed.sql` | trashed | 기본값 false |
| `004-details.sql` | pinned, color, 체크항목·라벨·연결 테이블 | 고정 false, 기본색; 기존 내용·시각·보관/휴지통 상태 유지 |

SQL은 `app/db/`에 있습니다. 일반 서버 시작에서는 `ddl-auto=validate`, SQL 자동 실행 금지를 유지합니다. 추가 변경은 위 준비 스크립트의 명시적 CLI에서만 실행합니다. 동명 테이블의 불일치나 DB 권한 문제는 파괴적인 초기화로 해결하지 않습니다.

이미 DB 준비가 끝난 상태에서 평소 실행할 때는 다음 명령도 사용할 수 있습니다.

```bash
./app/scripts/run-local.sh
```

두 스크립트 모두 Maven verify 성공 후에만 비밀번호를 입력받고 앱을 실행합니다. JAR 수정 시각은 검사하지 않습니다. 성공한 clean verify 후 JAR 시각이 1980-02-01이 되는 현상을 재현했으므로 파일 시각을 빌드 성공 기준으로 쓰지 않습니다.

## 사용법과 설계 규칙

- 전체 메모와 보관함은 보관 상태로 분리됩니다. 고정된 메모가 먼저 나오고 그 안에서 수정 시각 내림차순입니다.
- 검색은 제목·본문·체크항목에 대한 부분 문자열 검색이며, 보관 메모를 포함하고 휴지통은 제외합니다. 검색어는 앞뒤 공백 제거 후 200자 이내입니다. SQL 파라미터 바인딩을 사용하며 `%`, `_`도 일반 문자로 취급합니다.
- 삭제는 휴지통 상태 변경입니다. 복원하면 삭제 전 보관 상태로 돌아가며 내용·생성 시각을 유지합니다. 자동 기간 경과 삭제는 없습니다.
- 영구 삭제는 휴지통에서 확인 화면과 동의 체크를 거쳐 처리합니다. 휴지통의 편집·보관·체크 변경·고정·색상 변경은 서버에서도 거부합니다.
- 체크리스트는 편집창에서 한 줄당 한 항목으로 작성합니다. 완료 항목은 `[x] 항목` 형식입니다. 저장 후 완료 상태 버튼으로 체크/해제할 수 있습니다. 항목은 최대 100개, 항목당 200자입니다. 내용 없는 `[x]`, `[X]`, `[ ]`는 거부합니다. 항목 추가·제거는 줄 편집 후 저장으로 처리합니다.
- 라벨 관리에서 생성·이름 변경·삭제할 수 있습니다. 편집창에서 여러 라벨을 선택합니다. 라벨 삭제는 메모를 삭제하지 않습니다. 라벨별 목록은 보관 메모를 포함하고 휴지통은 제외합니다.
- 색상은 기본·노랑·초록·파랑·분홍 중 선택합니다. 빠른 설정 전에 편집 중 내용을 먼저 저장하세요.
- 제목 200자, 본문 10,000자. 제목·본문이 비어도 유효한 체크리스트가 있으면 저장됩니다. 서버 UTC 시각을 사용합니다.

검색 범위, 복원 위치, 필드 구조, 고정 정렬·색상·라벨·체크리스트 규칙은 원본 관찰이 없는 부분에 대해 **우리 앱의 설계 선택**입니다. 원본 Keep 연결 불가로 확인하지 못한 동작은 미확인으로 유지합니다.
